# devflow v0.4.0 优化总结

> 日期：2026-06-11
> 版本：0.3.3 → 0.4.0
> 路径：轻量路径（一次对话内完成）

---

## 一、本次优化的起因

积累了 2026-04-22 至 2026-05-09 的优化思路（见 `devflow-优化思路汇总.md`），核心痛点：

1. Apply 阶段频繁被文档更新打断实现节奏
2. state.md 全量追加导致后期膨胀，浪费 LLM token
3. session 两头（进入和退出）缺少自动化
4. 缺少原始需求存放位置
5. 延期项没有正式管理机制

---

## 二、本次做了什么（详细改动清单）

### 2.1 记录时机调整（核心改动）

**改动前**：每轮推进后至少更新 state.md，不分阶段。

**改动后**：分阶段策略——

| 阶段 | 记录行为 |
|------|----------|
| Align / Plan | 文档是阶段本身的交付物，正常产出 |
| Apply | **专注写代码，不主动更新过程文档**。代码全部完成后询问用户是否需要补文档 |
| 异常中断 | 检测到上下文压缩/用户暂停时，兜底写最小 state 快照（≤10 行） |
| 阶段切换 / Close | 正常更新 workflow / checkpoint / handoff |

**涉及文件**：
- `SKILL.md` 记录规则段落
- `references/recording-rules.md` 分阶段策略段落

---

### 2.2 state.md 分层

**改动前**：state.md 全量追加，越来越长。

**改动后**：
- `state.md` 只保留当前快照（≤30 行），每次更新时覆盖式写入
- 更新前先把旧内容 append 到 `state-history.md`（加时间戳分隔）
- LLM 默认只读 state.md，需要回溯时才读 state-history.md

**涉及文件**：
- `SKILL.md` state.md 分层规则段落
- `references/recording-rules.md` state.md 分层规则段落
- `assets/templates/state-template.md`（精简为 5 个字段的快照格式）
- `commands/devflow-handoff.md`（第 1 步加注分层操作）

---

### 2.3 新增 origin.md（原始需求）

**解决的问题**：mission 的"为什么要做这个"没有固定位置，散落在聊天记录里。

**规则**：
- Mission Init 时创建
- 内容包含：背景 + 目标 + 约束 + 参考链接
- 创建后**不再修改**（需求变更记入 decision-log）

**涉及文件**：
- `SKILL.md` 默认创建列表 + 优先信任列表
- `references/workspace-and-templates.md`
- `references/recording-rules.md`
- `assets/templates/origin-template.md`（新建）

---

### 2.4 新增 backlog.md + deferred/ 两层延期项管理

**解决的问题**：延期项缺乏管理，要么丢在聊天里忘了，要么需求多变时没法回顾。

**两层设计**：

| | backlog.md | deferred/ |
|---|---|---|
| 粒度 | 一句话 | 一个文件 |
| 适合 | 碎片灵感、可做可不做 | 明确延期的功能/逻辑 |
| 有无思路 | 没有，只是提一嘴 | 有，记录过讨论和方案 |
| 是否一定要做 | 不一定 | 是，只是不是现在 |
| 回顾方式 | handoff 时扫一眼 | resume 时检查触发条件 |

**deferred 文件必须写清**：
1. 暂不做的对象
2. 本轮不做的原因
3. 当前已有的思路
4. 后续触发条件
5. 推荐进入阶段

**禁止把"暂不做"写成永久放弃**。

**涉及文件**：
- `SKILL.md` 懒创建列表 + 优先信任列表
- `references/recording-rules.md`（新增两个段落 + 对比表）
- `references/workspace-and-templates.md`（目录结构 + 懒创建 + 模板时机）
- `assets/templates/backlog-template.md`（新建）
- `assets/templates/deferred-template.md`（新建）
- `commands/devflow-handoff.md`（新增第 9/10 步）

---

### 2.5 handoff command 优化

**改动前**：4 个检查项（0.3.0），后升到 9 个（0.3.3），缺少 backlog 和顺序问题。

**改动后**（10 个检查项，顺序调整）：
1. state.md（含分层操作提示）
2. workflow.md
3. bug-log
4. plans
5. learnings
6. decision-log
7. checkpoint（含归档逻辑）
8. spec
9. **backlog**（新增，在 handoff 之前）
10. **handoff**（移到最后，因为可引用 backlog 内容）

---

### 2.6 内部一致性修复（skill-creator 审查发现）

| 问题 | 修复 |
|------|------|
| 铁律第 4 条与 Apply 新规则有冲突感 | 加注：Apply 内不写 checkpoint 但回退时要写 |
| recording-rules checkpoint 段落未体现新规则 | 加前置规则 + 新增第 7 条"Apply 中发生阶段回退时" |
| handoff command 中 backlog 放在 handoff 之后 | 调整顺序，backlog 在前 |

## 三、本次没做的（以及原因）

| 方向 | 不做原因 |
|------|----------|
| 嵌套 spec / sub-mission | 增加复杂度，LLM 处理嵌套容易迷路。替代方案：拆多个 mission + decision-log 记录依赖 |
| 自动创建 cmd 指向 NEXT-SESSION-PROMPT | session-lifecycle 的 resume 流程已覆盖此需求 |
| package.json 版本号同步自动化 | 放入 backlog，优先级低 |
